# docs handoff ルール

この文書は、作業が途中で止まっても別エージェントへ安全に引き継げるようにするための最低基準を定める。

## 目的

- チャット履歴に依存せず、`docs` だけで再開できるようにする
- どこまで終わったか、どこで止まったか、次に何をするかを明確にする
- 推測で再開させず、観測事実と判断を残す

## 停止点で必ず残すもの

- 今何を達成しようとしていたか
- どのファイルをどう変えたか
- 実行したコマンドと結果
- 未完了の作業
- 次に最初にやる 1 手
- ブロッカーと、その解除条件
- 重要な判断と仮定

## どこに書くか

- 現在の要求: `docs/REQS.md`
- 複雑作業の全体計画: `docs/EXECPLAN_*.md`
- 直近の停止点と次の一手: `docs/WORKLOG.md`

## 良い handoff の条件

- 「たぶんこうだろう」で埋めなくてよい
- 次のエージェントが最初に開くファイルと最初に打つコマンドが分かる
- 失敗した試行も、価値があるなら残っている
- 未確認部分が明示されている

## 悪い handoff の例

- 「途中です。続きお願いします」
- 「だいたい終わった」
- 「テストしてません」
- 「この辺を見れば分かると思う」
