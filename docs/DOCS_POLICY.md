# docs 運用方針

## 目的

docs は「仕様」「計画」「検証結果」「再開情報」を残す場所とする。
チャットログだけでは再開できない状態を避ける。
停止や担当エージェントの交代が起きても、`docs` だけで作業継続できる状態を保つ。

## ルール

- 永続ルールは `AGENTS.md` / `CLAUDE.md` / `.claude/rules/` に書く。
- 作業ごとの要求は `docs/REQS.md` に書く。
- 複雑作業の手順と判断は `docs/EXECPLAN_*.md` に書く。
- 途中経過と停止点は `docs/WORKLOG.md` に追記する。
- docs を更新したら `docs/INDEX.md` も更新する。
- 同じ説明を複数文書へ重複して書きすぎない。初回読込コストを増やすだけの重複は避ける。
- 停止点では、次のエージェントが最初に読むべき文書、次に実行すべきコマンド、未解決事項を docs に残す。
- 「あとで見れば分かる」は禁止。再現手順、対象ファイル、判断理由を docs に落とす。

## 品質基準

- 受け入れ条件は人が観測できる形で書く。
- 実行コマンドと期待結果をセットで残す。
- 曖昧な抽象論ではなく、対象ファイル、対象コマンド、対象ふるまいまで落とす。
- 停止点の記録は、別エージェントがそのまま着手できる具体性を持たせる。
