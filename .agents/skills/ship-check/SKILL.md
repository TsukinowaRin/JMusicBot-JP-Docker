---
name: ship-check
description: 実装の終盤で、変更範囲の検証、実施した確認の要約、残リスクの明示を行うために使う。小さくないコード変更の後、commit 前、レビュー依頼前に使う。純粋なブレインストーミングには使わない。
---

1. 変更ファイルに対して最小で有効な検証を決める。
2. 必要な test、build、type-check、lint、smoke check を実行する。
3. 検証できないものがあれば、理由と未確認範囲を明記する。
4. diff を見て、意図しない変更、docs 更新漏れ、危険なコマンドが無いか確認する。
5. 何を変えたか、何を検証したか、何が残リスクかを要約する。
6. checkpoint commit を使う repo なら、そのまま commit や PR の説明へ転記できる形にする。
